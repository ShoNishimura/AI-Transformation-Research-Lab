# RLS-000 ドキュメント作成規約

## 1. 目的

Research Lab におけるドキュメントの一貫性、可読性および保守性を確保するため、本規約を定める。

---

## 2. 適用範囲

本規約は、Research Lab で管理するすべてのドキュメントに適用する。

対象例

- README
- Charter
- Standards (RLS)
- Handbook
- LAB
- Research Question (RQ)
- Evidence (E)
- Verification
- Milestones

---

## 3. 命名規則

### 3.1 フォルダ

フォルダ名は英語を使用する。

例

- charter
- standards
- handbook
- templates

---

### 3.2 ファイル

ファイル名は英語を使用する。

単語はハイフン (-) で区切る。

例

- README.md
- HANDBOOK.md
- MILESTONES.md
- RLS-001-Evidence-Card-Standard.md
- LAB-001-Research-Environment-Setup.md

---

### 3.3 管理ID

管理IDは英語で統一する。

例

- RLS-001
- LAB-001
- RQ-001
- E-001

管理IDは一度使用した番号を再利用しない。

---

## 4. 記述ルール

### 4.1 記述言語

本文は日本語を正本とする。

専門用語は必要に応じて英語を併記する。

例

- 研究課題（Research Question）
- エビデンス（Evidence）

---

### 4.2 見出し

見出しは日本語で記述する。

推奨見出し

- 目的
- 背景
- 対象
- 仮説
- 検証方法
- 結果
- 考察
- 結論
- 今後の課題

---

### 4.3 Markdown

GitHub 標準の Markdown 記法を使用する。

HTML は必要最小限とする。

---

### 4.4 表記

Microsoft 製品名は公式名称を使用する。

例

- Microsoft 365 Copilot
- Microsoft Graph
- SharePoint
- OneDrive
- Copilot Memory

略称を使用する場合は、初出時に正式名称を記載する。

---

### 4.5 テンプレート

新規ドキュメントを作成する場合は、可能な限り Research Lab が定めるテンプレートを利用する。

テンプレートが存在しない場合は、本規約に従って作成する。

---

## 5. 改訂

本規約は Research Lab の運用状況に応じて見直す。

改訂履歴は GitHub の変更履歴を正本とする。
